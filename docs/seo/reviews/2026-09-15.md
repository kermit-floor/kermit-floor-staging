### Live consent/analytics finding

Isolated Chromium contexts checked English desktop, Turkish desktop and a Turkish
mobile viewport, including fresh acceptance and reload with saved consent. No GA
script initializes before acceptance. After acceptance the loader initializes,
saved consent restores, one page-view command is generated per tested page load,
and no page JavaScript error is reported. Collection requests were intercepted and
blocked so the review did not send synthetic analytics events.

However, **all three contexts queue the first `page_view` before the consent-granted
update**, after configuring analytics with a denied default. A focused Turkish
network check reproduces the differing consent signals: first page-view request
`gcs=G1-0`, later engagement request `gcs=G1-1`, including after reload. The recorded
command sequence is the evidence; the site should apply the accepted choice before
it emits its initial page view. Google's guidance describes persisting consent and
applying the update on subsequent pages, with updates made before navigation.
[Consent implementation guidance](https://developers.google.com/tag-platform/security/guides/consent).

This is a concrete measurement concern, **not proof of the August desktop decline's
cause**. Git history shows the initialization/consent sequence already existed before
August; the August 15 tracking commit only added `trackEvent`. It reproduces on the
mobile control as well. Ad blockers, browser-specific behaviour, real consent rates
and consent-denied visitor counts were not measured here.

**Recommended next implementation:** apply accepted analytics consent before the
first page-view event, retain rejection behaviour, and verify fresh accept, saved
accept, reject and internal navigation with analytics delivery blocked. Before any
ship, record its site-wide measurement interference and re-baseline affected GA4
outcomes; do not reset GSC-only ranking comparisons unnecessarily. This repair was
not implemented or authorized as a new website change in this review. Recheck the
desktop observation on **September 17** alongside the weekly lead read.
