### Newly observed sitemap coverage gap

The live sitemap exposes the nine new English articles as `<loc>` entries, but the
nine Turkish articles only as `xhtml:link` alternates. The Turkish wall-panel product
has the same pattern. This clarifies earlier reports' loose wording that all URLs
were "in the sitemap": they are present in its text, but not all are URL entries.
The saved evidence distinguishes `sitemap_loc` from `sitemap_alternate`.

`src/app/sitemap.ts` emits English-only URL entries for static routes and article
pairs. Its last recorded change is February 8, so this is an existing implementation
gap, not a September release regression. Google's sitemap hreflang guidance calls
for a separate URL entry for each language version, each listing all alternates.
[Official localized-page sitemap guidance](https://developers.google.com/search/docs/specialty/international/localized-versions#sitemap).

**Recommend a sitemap correction after the September 27 structural review**, with
reciprocal EN/TR entries and exact URL/alternate checks. It overlaps site-wide
discovery and must receive a recorded interference treatment if shipped earlier.
This review does not authorize or implement the change. Existing Turkish indexing,
and the excluded English guide, prevent attributing the two exclusions or wall-panel
loss to this gap. No indexing benefit is promised.
